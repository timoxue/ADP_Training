    场景四：交易执行质量分析（TCA）¶

    交易部 / 机构交易柜台 · 从成交明细到执行质量报告

    使用场景¶

    券商机构交易柜台每天需要对当日执行的订单做交易成本分析（Transaction Cost Analysis, TCA）：算滑点、比 VWAP、看算法表现、找出执行差的订单。以往这些工作要在 Excel 里手工透视表 + VLOOKUP，还要额外画图工具。以下演示用 Claude Code 一次跑通「读数据 → 算指标 → 画图 → 出报告」全链路。

    前置准备¶

    安装 Python 分析依赖（仅需执行一次）：

    pip install pandas matplotlib plotly openpyxl

    操作步骤¶

    步骤 1：启动 Claude Code¶

    claude

    步骤 2：了解数据概况¶

    读取当前目录的 trading_log.csv，告诉我：
1. 今天一共执行了多少笔订单，总成交金额是多少
2. 买入 vs 卖出的笔数和金额分布
3. 涉及哪几位交易员、哪几种算法

    预期输出：

    今日共执行 20 笔订单，总成交金额约 7.68 亿元。

    方向分布：买入 12 笔（约 4.35 亿元），卖出 8 笔（约 3.33 亿元）。

    交易员：张伟、李娜、王强、赵敏 4 人，每人 5 笔。 算法：VWAP（8 笔）、TWAP（4 笔）、POV（4 笔）、ICEBERG（4 笔）。

    步骤 3：计算 VWAP 滑点，找出最优 / 最差订单¶

    针对每笔订单，计算两个执行质量指标：

1. VWAP滑点（bps）= (委托均价 - 市场VWAP) / 市场VWAP × 10000
   注意方向：买入时滑点为正表示成本超基准（差），卖出时滑点为负表示卖价低于基准（差）
   统一转换为「相对基准的成本」——买入正为差、卖出负为差

2. 实施差额IS（Implementation Shortfall, bps）
   = (委托均价 - 到达价) / 到达价 × 10000（买入方向，卖出取反）

按 IS 从最差到最优排序，找出：
- Top 3 最差执行的订单（成本最高）
- Top 3 最优执行的订单（成本最低甚至负成本）
用表格输出：订单号 / 交易员 / 股票 / 方向 / 算法 / VWAP滑点 / IS

    预期输出（节选）：

    执行最差 Top 3

    订单号 交易员 股票 方向 算法 VWAP滑点(bps) IS(bps)
    T20241015010 李娜 恒瑞医药 买入 VWAP +48.5 +115.3
    T20241015003 李娜 宁德时代 卖出 POV +66.7 +136.6
    T20241015008 赵敏 中信证券 买入 TWAP +57.6 +125.0

    执行最优 Top 3

    订单号 交易员 股票 方向 算法 VWAP滑点(bps) IS(bps)
    T20241015007 张伟 平安银行 卖出 VWAP -58.2 -124.0
    T20241015014 李娜 美的集团 卖出 VWAP -34.4 -68.6
    T20241015019 王强 中国建筑 卖出 TWAP -55.0 -109.5

    步骤 4：按算法 / 交易员两个维度做归因¶

    基于上述指标，做两组归因分析：

1. 按算法分组：每种算法的平均 IS、订单数、总成交金额
   哪种算法在今日整体行情下表现最好？

2. 按交易员分组：每位交易员的平均 IS、订单数、命中率（IS < 0 的比例）
   哪位交易员执行质量最稳？

结果用两张表格输出，并给出一句话结论

    预期输出（结构示例）：

    按算法维度

    算法 订单数 平均IS(bps) 成交金额(万元)
    VWAP 8 -12.5 32,140
    TWAP 4 +18.3 12,760
    POV 4 +25.6 17,850
    ICEBERG 4 -8.4 14,020

    结论：今日行情下，VWAP 和 ICEBERG 算法表现较好；POV 算法在追盘时明显吃亏（正 IS 表示成本高于到达价）。

    步骤 5：生成可视化图表¶

    帮我写一个 Python 脚本，读取 trading_log.csv，生成以下图表并保存为 HTML 文件：

1. 每笔订单的 IS 散点图，X 轴订单号，Y 轴 IS(bps)，颜色按算法区分，
   过零线画红色虚线（正为差、负为优）

2. 按算法分组的 IS 箱线图（Box Plot），看哪种算法波动最小

3. 按交易员分组的 IS 柱状图，展示平均 IS

使用 plotly 库，中文标题，保存为 tca_report.html

    Claude Code 生成脚本后，继续输入：

    请运行刚才生成的脚本

    步骤 6：生成柜台日报邮件¶

    基于上面所有分析，帮我写一份给机构交易总监的日报邮件，主题简洁明确，正文包含：

1. 今日执行总览（订单数、成交金额、平均IS）
2. 执行亮点（1-2 条）
3. 需要关注的问题（点名最差订单，客观陈述原因推测——如追涨杀跌、算法与行情不匹配等）
4. 明日执行建议（1-2 条）

控制在 400 字以内，语气专业克制

    预期输出：

    主题：【交易柜台日报】10月15日执行质量分析——4 笔订单需复盘

    总监：

    今日总览：共执行 20 笔订单，成交金额 7.68 亿元，全日加权平均 IS 约 +2.5 bps，整体略高于基准。

    执行亮点 - 张伟负责的平安银行 8 万股卖出单，VWAP 算法节约成本约 58 bps - VWAP 算法整体表现最稳，平均 IS -12.5 bps

    需关注问题 - 李娜负责的宁德时代 POV 卖出单，IS 达 +136.6 bps，建议复盘算法参数与市场冲击匹配度 - POV 算法整体平均 IS +25.6 bps，在震荡行情下追盘特征明显

    明日建议 - 大单卖出优先考虑 VWAP 或 TWAP，谨慎使用 POV - 对连续两日 IS > 100 bps 的订单启动逐笔复盘

    步骤 7（可选）：导出复盘 Excel¶

    把执行最差的 5 笔订单导出为 Excel 文件，文件名 tca_review_20241015.xlsx，
包含：原始订单数据 + 计算的 VWAP滑点 / IS / 相对到达价的执行方向偏离
加一个"复盘要点"Sheet，列出这 5 笔的可能原因和建议

    适用更多场景

    同样的方式可以用于：算法交易参数回溯、大宗交易执行分析、多日 TCA 汇总、经纪商执行质量对比、股指期货基差监控等任何需要「读数据 → 算指标 → 出报告」的交易柜台日常。

    关于 TCA 指标

    本演示使用两个最常用指标：VWAP 滑点（相对区间成交量加权均价的偏离）和 Implementation Shortfall（相对下单瞬间市价的偏离）。实际生产系统还会考虑市场冲击成本、机会成本、时机成本等维度，可按需要扩展。
